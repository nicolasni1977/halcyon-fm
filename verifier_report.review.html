Issues

critical (2)

CRIT-001 Submenu rendering hard-caps at 8 items; selection past index 7 invisible functional_regression
ScreenRenderer.renderSubmenu uses items.slice(0,8) before rendering rows. When the menu has >8 items (e.g. an artist with many tracks, an All Songs list), wheel-scrolling past index 7 updates appState.selectedIndex but the row never appears in the pane — the user sees no feedback for scrolls 8..N. Scroll indicator is shown but list does not scroll.
index.html · ScreenRenderer.renderSubmenu · renderSubmenu function body
fixCompute a window: const start = Math.max(0, Math.min(items.length-8, appState.selectedIndex-7)); const visible = items.slice(start, start+8); then render with (start+i) === selectedIndex selection check, and toggle scroll indicators top/bottom based on start.
CRIT-002 Power-off immediately re-boots because WheelEngine pointerup still fires PLAY_PAUSE functional_regression
An auxiliary pointerdown listener on #wheel-outer starts _playLongTimer for bottom-sector and dispatches POWER_OFF at 1500ms. But WheelEngine's own pointerup handler runs on release, detects bottom sector with low drag distance, and dispatches PLAY_PAUSE. In handlePlayPause, when state===OFF it dispatches POWER_ON. Net effect: holding bottom for 1.5s powers off AND immediately powers back on.
index.html · #wheel-outer event bindings + WheelEngine._bindWheel pointerup · Event Bindings section (_playLongTimer) and WheelEngine._bindWheel
fixMove the long-press logic INTO WheelEngine: on pointerdown record startTime and target sector; on pointerup, if sector==='PLAY_PAUSE' and (Date.now()-startTime)>=1500 dispatch POWER_OFF and SKIP the regular sector dispatch (early return). Remove the separate _playLongTimer pointerdown listener.

major (5)

MAJ-001 Click-wheel inner cutout shows brushed-aluminum gradient, not a recessed plastic hole visual_design
#wheel-outer::after fills the inner 56% with the SAME body gradient (radial 40%/30% + grain + lighting). On a real iPod the area under the center button is the white plastic ring continuing INWARD, not the silver body. The result reads as a hole punched through to the case rather than a circular recess.
index.html · #wheel-outer::after
fixReplace the ::after background with a flat #C8CACE or a very subtle radial gradient (#D8D8D8 → #C8C8C8) — no grain stripes — and add inset shadow inset 0 2px 4px rgba(0,0,0,0.2) to suggest a recessed well.
MAJ-002 Cover Flow card images leak object URLs on every re-render code_quality
renderCoverFlow creates URL.createObjectURL(album.coverBlob) for each card every time it runs; img.onload revokes that specific URL but if the user scrolls quickly through cards, prior renders' image-loads may not fire before the next render replaces the parent, leaking blob URLs. Same pattern in updateArtForCurrentMenu for sub-pane.
index.html · renderCoverFlow / updateArtForCurrentMenu
fixCache blob→URL mapping on a Map keyed by track.id, generate URL once on library load, reuse on every render. Only revoke on track delete.
MAJ-003 Quick-scroll overlay shows letter of CURRENTLY selected item, not the upcoming alphabetical jump ux_navigation
_showQuickScroll renders list[appState.selectedIndex][0]. The spec describes the iPod behavior as 'releasing wheel jumps selection to next item starting with that letter', i.e. the letter shown should be the current alphabetical bucket and on release selection should snap to that letter. Current implementation just shows the letter of whatever row is currently highlighted (which is moving every tick anyway).
index.html · WheelEngine._showQuickScroll
fixGroup sorted list into A-Z buckets, track an _activeBucket that increments by one letter every N ticks of high-velocity scrolling, render the bucket letter, and on pointerup snap selectedIndex to the first item in that bucket.
MAJ-004 Marquee for long Now Playing title uses fixed 8s loop irrespective of title length ux_navigation
@keyframes marquee animates -50% translateX over 8s for ALL title lengths; very long titles scroll fast and very short titles (just over 15 chars) scroll painfully slow. The 30%-70% hold-then-scroll keyframe pattern also pauses awkwardly.
index.html · .status-marquee-inner / @keyframes marquee
fixCompute the title pixel width on render, set animation-duration via inline style proportional to width (px / 30 = seconds for ~30 px/s), and simplify keyframes to a plain 0% translateX(0) → 100% translateX(-50%) loop with a CSS animation-delay for the initial hold.
MAJ-005 Bottom-edge dock slot and headphone jack are inside #ipod-device but no constraint prevents overflow on small scales code_quality
On small viewports recalcScale shrinks the wrapper but #ipod-wrapper.width=257 / height=430 stays the layout box. flexbox centers, but margin: 40+20 px reserved is per-side, not symmetric. On viewport widths < 277 px (257+20) the wrapper visually clips by 1-2 px on phones, especially with notch insets — no viewport-fit=cover safe-area handling.
index.html · <meta name=viewport> + recalcScale
fixAdd viewport-fit=cover to the meta tag, wrap the body in padding: env(safe-area-inset-top) env(safe-area-inset-right) env(safe-area-inset-bottom) env(safe-area-inset-left); and in recalcScale use document.documentElement.clientWidth/Height which respects safe areas.

MIN-005 Center-button long-press fires context menu in any state, even MAIN_MENU where Browse Artist makes no sense ux_navigation
